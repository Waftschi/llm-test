Learning in miniature

How “kein” is learned

1

Input

teach it in the console

[start] kein bier = wein

The guest tells the barkeeper what would have been right: sentence, context and the correct answer.

2

Save

new row in examples

start | kein bier | wein

The example goes into the database next to the existing ones. It is the learning material; nothing in the network changes yet.

3

New column

word “kein” into the vocabulary

W1: column “kein”

Before, “kein” was unknown and ignored. Now it gets its own column in W1, with a random start for every concept.

4

Retrain

all examples, 1500 rounds

error → backprop

The network guesses for every sentence, measures the error and nudges the weights (slides 10 and 11). For “kein bier” training pulls the weights of “kein” so that they hold back bier votes and push wein votes.

5

Result

what was learned lives in the weights

bier 99.9 % → wein 98.9 %

“kein” is not an entry in a list; it lives in the numbers of W1 and W2. The sentence “kein bier” now gives wein.

This is how a sentence becomes a learned relationship. The guest types “kein bier = wein” in the console. The example is stored in the table examples. Because “kein” is missing from the vocabulary, a new column appears in W1. Then the whole network is retrained: from the random start, with all stored examples, 1500 rounds. So not only the word “kein” is changed, all weights are recalculated. How exactly the weights are nudged is shown on the backpropagation slides. Important: the network does not get a rule “kein flips the answer”. It finds weights that work for the examples. That is why it needs several examples; in our model there are 14 with “kein”, so that similar sentences like “kein wein” or “bitte kein bier” also work. The numbers come from a model with these 14 examples compared to a model without any of them.
